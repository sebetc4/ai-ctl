### 1. The generated llama-swap configuration leaves the gateway open to any local process and any web page

- **Axes:** security — raised by `review-security`
- **Action:** fix
- **Severity:** medium
- **Where:** `src/domain/gateway_config.rs:394-418`, `src/domain/gateway_config.rs:449`, `src/infrastructure/http.rs:65-66`
- **Cause:** `to_yaml` writes no `apiKeys` and no origin limit, and llama-swap v263 checks no
  `Host` header and answers every origin with `Access-Control-Allow-Origin: *`; ai-ctl's
  clients send no credential.
- **Consequence:** any local process or user, and any web page open in the user's browser —
  without DNS rebinding, since CORS `*` lets a cross-origin page read the answers — can call
  `/v1/chat/completions`, `/upstream/<model>/…`, `/running`, `/logs` and
  `/api/models/unload`: load a ~22 GB model or evict the one in use (a GPU denial of
  service), read the log stream, where `logToStdout: "proxy,upstream"` puts the models'
  output, and use the GPU for free. Only a browser's own local-network blocking stands in
  the way of a page.
- **Fix:** keep one API key in ai-ctl's state, not a new one at each `up`, which would break
  OpenCode's `"apiKey"` (`deploy/opencode.json:9`) and the note of `docs/stack.md:381`;
  write it as llama-swap's `apiKeys` and send it as `Authorization: Bearer` from
  `gateway_api`, `server_api` and `chat_api`. `/health` stays open, so `up`'s readiness probe
  (`gateway_api.rs:75`) needs no key. The llama-server backends on `127.0.0.1:${PORT}` stay
  open to local processes: pass them `--api-key`, or say the key guards the gateway only.
  `allowedOrigins` is untested.
- **Evidence:** read: `to_yaml` writes `logToStdout`, `models`, `routing` and `hooks` only;
  `strings` on the v263 binary shows `apiKeys` and `allowedOrigins`.
- **Verification:** CONFIRMED — the installed llama-swap v263 run alone on
  `127.0.0.1:18999` with a configuration without `apiKeys`: `/v1/models` and `/running` 200
  with `Host: attacker.example:18999`; 200 with `Access-Control-Allow-Origin: *` for
  `Origin: https://attacker.example`; a POST preflight 204 allowing every method and
  `content-type`; `/logs` 200; `POST /api/models/unload` from that origin 200. With
  `apiKeys: ["k-secret"]`, all of them 401 without the key, `/v1/models` 200 with
  `Authorization: Bearer k-secret`, `/health` 200 without it.

### 2. Paths compared with `/proc/<pid>/exe` are never canonicalized, so a symlink in the data directory hides the running gateway and the leftover check

- **Axes:** bugs — raised by `review-correctness`
- **Action:** fix
- **Severity:** medium
- **Where:** `src/infrastructure/gateway_process.rs:90-99`, `src/infrastructure/build_store.rs:283-286`, `src/infrastructure/paths.rs:28-46`
- **Cause:** `liveness_of` compares the record's `binary`, built from `Paths`, which keeps
  `HOME` and `XDG_DATA_HOME` as given, with `/proc/<pid>/exe`, which the kernel gives
  resolved. `FsBuildStore::contains` does `program.starts_with(&self.root)` with the same
  unresolved root.
- **Consequence:** with the data directory reached through a symlink (moved to another disk,
  say), `up` starts and records llama-swap; the next `status` sees `Liveness::Reused` and
  removes the record (`lifecycle.rs:460-468`); `down` answers "No gateway running" while
  llama-swap and its models hold the GPU, and `up` stops on the taken port
  (`lifecycle.rs:208`). `contains` is false for every build binary, so the leftover check
  (`lifecycle.rs:541-543`) misses models a killed gateway left on the GPU. It needs a
  user-made symlink: on this machine's layout it does not fire.
- **Fix:** resolve at the comparison, not in the record: in `liveness_of`, compare the link
  with `fs::canonicalize(binary)` (for a removed file, canonicalize its parent and add the
  file name and " (deleted)"); in `FsBuildStore::contains`, compare with
  `fs::canonicalize(&self.root).unwrap_or(root)`, the pattern of `host.rs:136`. Add a test
  with a symlinked root.
- **Evidence:** reproduced by a throwaway crate starting a binary through
  `LocalGateway::start`: canonical directory `liveness=Running`, `contains = true`; the same
  directory through a symlink `liveness=Reused(Some(".../real/llama-swap/v263/llama-swap"))`,
  `contains = false`.
- **Verification:** CONFIRMED — rerun against the working tree with the same result. The
  reviewer's other fix, canonicalizing the recorded binary, would break `is_current`
  (`lifecycle.rs:449`), which compares the record with an unresolved target: `up` would
  refuse a running gateway as another configuration.

### 3. A Unicode line separator in an inventory value breaks out of the `cmd: |` block and makes llama-swap run a command on the host

- **Axes:** security — raised by `review-security`
- **Action:** fix
- **Severity:** low
- **Where:** `src/domain/gateway_config.rs:363-377`, `src/domain/gateway_config.rs:423-427`, `src/domain/gateway_config.rs:493-500`
- **Cause:** `Text::checked` refuses `${` and `char::is_control` characters only
  (`gateway_config.rs:370`), which leaves U+2028 and U+2029; `shell_word` quotes the word
  but keeps the character, and `write_model` writes it in a literal block scalar, which
