## Decisions

- **The start commit lives only in the archive.** The new history cannot reach `1a49576`, so this phase's Files Changed is computed from the new repository (every tracked file is added) and the v1 deletions are listed from the archive bundle.
- **`deploy/models.ini` uses a `${MODELS_DIR}` placeholder** instead of a hard-coded host path. Phase 1's `init` substitutes it; the same file then serves the native and container runtimes, the container mounting the models at their host paths (phase 3).
- **`main.rs` is the composition root.** Presentation never imports infrastructure; `main` wires adapters into use cases and hands them to `presentation::run`. Later phases extend `run`'s parameters instead of building adapters in presentation.
- **No async runtime yet.** The skeleton is synchronous; `tokio` arrives with the first phase that needs concurrent I/O.
- **llm-ctl targets production, not learning** (the user's correction during the phase). `CLAUDE.md`, `docs/architecture.md` and the roadmap README no longer frame it as a learning project; Clean Architecture stays, justified by testability. Later phases favour robustness and failure-path tests over illustrative code.
- **`authors` holds the git user name only**, not an e-mail address, since the repository may become public.

- `main.rs` is the composition root: adapters are wired there, never in presentation.
- This machine still has `nvcc` 13.2, GCC 16.2.1 by default and GCC 15 installed, and a driver supporting CUDA 13.4: `doctor`'s first real run should flag the toolkit.
