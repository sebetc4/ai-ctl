# OpenWebUI

OpenWebUI is the client for daily use of the gateway: chat, dictation, answers read aloud, images
made and edited. ai-ctl does not manage it. This guide says how to run it and how to set each of
these uses, and what each setting does to the gateway. Checked with OpenWebUI 0.12.3: the chat on
2026-10-12, speech and images on 2026-10-30. The image §1 pins, OpenWebUI 0.13.0 built on
2026-11-03, was compared with 0.12.3 on 2026-11-06, both images' files read from podman's store:
the requests its chat, speech and image settings send to the gateway, in its backend, and the
labels below, in its English and French interfaces, are unchanged.

What OpenWebUI sends to each server, and how each fits, is in the server's document:
[whisper-cpp.md §5](audio/whisper-cpp.md#5-openwebui),
[audio-cpp.md §6](audio/audio-cpp.md#6-openwebui) and
[stable-diffusion-cpp.md §5](image/stable-diffusion-cpp.md#5-openwebui).

---

## 1. The Container

OpenWebUI runs in a rootless podman container whose network reaches the host's loopback:

```bash
podman run -d --name openwebui -p 127.0.0.1:18000:8080 \
  --network=slirp4netns:allow_host_loopback=true \
  -v open-webui:/app/backend/data \
  ghcr.io/open-webui/open-webui:main@sha256:5defa46451d991ddb0105211593c075149c7018f193191ad94b52603bda3cf1c
```

- Open `http://127.0.0.1:18000`. After a reboot, `podman start openwebui` starts it again with
  its settings, which live in the volume `open-webui`.
- Publish it on loopback only, `127.0.0.1:18000`: [security.md §6](security.md#openwebui-on-loopback)
  says what `-p 18000:8080` would open.
- Inside the container, `127.0.0.1` is the container itself; `allow_host_loopback` makes the
  host's loopback `10.0.2.2`, so the gateway is **`http://10.0.2.2:8080/v1`**.
- Use the `:main` image (CPU), not `:cuda`, to leave the VRAM to the models.
- The digest, that of the image's linux/amd64 manifest, pins the image this page was checked
  with: podman runs it whatever `:main` names now, and the container holds the key (§3). To move
  to a newer image, pull `:main`, check this page with it, and pin the digest
  `podman image inspect --format '{{.Digest}}' ghcr.io/open-webui/open-webui:main` prints.
  Decided: 0.13.0, the image running here since 2026-11-04 (the user, 2026-11-05, in the fixes
  of `audio-image-backends`' review). Set aside: 0.12.3, the image the page was first checked
  with, older than the migration 0.13.0 made of the volume `open-webui`.
- Environment variables apply only on the first start; after that, the settings saved in the
  interface win.

## 2. The Settings

The avatar's menu, bottom left, opens two places:

- **Settings** (Réglages) opens one dialog holding both your own settings, under **Personal**
  (Personnel), and OpenWebUI's, under **Administrator** (Administrateur): every setting below is
  there.
- **Admin Panel** (Panneau d'administration) opens the users, evaluations and functions first; its
  Settings tab leads to the same dialog.

Each page has its own **Save** (Enregistrer) button, bottom right. The labels below are the
English interface's, the French interface's in parentheses where they differ.

A value typed in a field is sent as typed: a model saved as `" qwen3-tts"`, a space first, is a
model the gateway does not know. Retype a field that fails rather than looking for another cause
first.

---

## 3. The Key

Every request to the gateway but `/health` needs ai-ctl's key ([stack.md §7](stack.md#7-client-configuration)).
OpenWebUI holds it in five settings, each pasted by hand: the chat's connection (§4), speech to
text (§5), text to speech (§6), image generation and image editing (§7). Copy it to the clipboard
without showing it:

```bash
tr -d '\n' < ~/.local/state/ai-ctl/api-key | wl-copy
```

When the key changes, paste it again in all five. Never type it into the login prompt a browser
shows for llama-swap's own web page ([stack.md §7](stack.md#7-client-configuration)).

## 4. Chat

**Administrator → Connections** (Connexions), **OpenAI API** (API compatibles OpenAI):

| Setting | Value |
|---|---|
| The connection to `https://api.openai.com/v1` created by default | Off |
| A connection to `http://10.0.2.2:8080/v1` | On, ai-ctl's key as its key |
| **Ollama API** (API Ollama) | Off |

OpenWebUI 0.12 creates an OpenAI connection with the Responses API (`/v1/responses`), and calls
tools natively: every chat carries its built-in tools, 7.1K tokens on the 27B, evaluated on a
chat's first message and taken from the cache after it. With a chat's first message it also sends
a short task request, which the single slot serves before the answer: 2.7 s on the 27B.
Checked on 2026-10-12: reasoning and answer streamed, title and follow-ups generated by the
chat's model, a second turn taking 7130 of its 7269 tokens from the cache.

**Administrator → Models** (Modèles) lists every model the gateway serves, the speech and image
models included, and the chat's model selector offers them all, though none of them can chat.
Turn off every model but the chat models, `qwen3.8-27b` and `qwen3.6-35b-a3b`: the selector then
offers those alone. Speech and images name their model in their own settings (§5 to §7), which
do not read this list. A model added to the inventory appears turned on.

**Administrator → Interface** (Interface utilisateur), **Tasks** (Tâches):

- **Task Model** (Modèle pour les tâches) left empty, which OpenWebUI reads as the current chat
  model: a title or a follow-up never swaps in another model. Naming one model there would load
  it after every chat with the other.
- **Autocomplete Generation** (Génération des suggestions) off: it sends a request at every pause
  in typing. Keep **Title Generation** (Génération du Titre).

With `parallel = 1`, a question asked while an agent runs waits for the agent to finish
([stack.md §6.5](stack.md#65-settings-not-to-miss)).

## 5. Speech to Text

**Administrator → Audio**, **Speech-to-Text** (Reconnaissance vocale):

| Setting | Value |
|---|---|
| **Speech-to-Text Engine** (Moteur de reconnaissance vocale) | `OpenAI` |
| **API Base URL** (URL de base de l'API) | `http://10.0.2.2:8080/v1` |
| **API Key** (Clé API) | ai-ctl's key |
| **Request Format** (Format de la requête) | Multipart, as set by default |
| **STT Model** (Modèle de Speech-to-Text) | `whisper-large-v3-turbo`, typed |

**Personal → Audio**, **STT Settings** (Réglages de Speech-to-Text):

- **Speech-to-Text Engine** on **Default** (Par défaut), the administrator's engine. **Web API**
  (API Web) would use the browser's recognition instead.
- **Language** (Langue) `fr`, or the language you speak. OpenWebUI sends a language only when this
  is set, and `whisper-server` guesses it otherwise: on 2026-10-30, 2.2 s of French came back as
  Icelandic, detected with a probability of 0.96. Set, the same sentence came back right.

To dictate, click the microphone in the input bar, **Voice Input** (Saisie vocale), speak, then
the ✓ to confirm; the text lands in the input bar. The waveform beside it starts a voice call
instead. The first dictation loads the model, about 2 s.

## 6. Text to Speech

**Administrator → Audio**, **Text-to-Speech**:

| Setting | Value |
|---|---|
| **Text-to-Speech Engine** (Moteur de Text-to-Speech) | `OpenAI` |
| **API Base URL** (URL de base de l'API) | `http://10.0.2.2:8080/v1` |
| **API Key** (Clé API) | ai-ctl's key |
| **TTS Model** (Modèle de Text-to-Speech) | `qwen3-tts`, typed over `tts-1` |
| **TTS Voice** (Voix de Text-to-Speech) | A voice of the library, such as `micode-fr`, typed over `alloy` |
| **Additional Parameters** (Paramètres supplémentaires) | `{}` |
| **Response Splitting** (Division de la réponse) | Punctuation: one request per sentence |

- OpenWebUI asks for the models and the voices without the key, gets llama-swap's 401, and offers
  OpenAI's instead: type the model and the voice.
- The cloning models' voices are the library's: each `<voice>.wav` in `/ai/models/voices/`, named
  without `.wav`, with its transcript in `prompt_text`
  ([audio-cpp.md §3](audio/audio-cpp.md#3-serving)).
- **Personal → Audio**: **Text-to-Speech Engine** on **Default** (Par défaut). **Set Voice**
  (Choisir la voix) holds your own voice, the administrator's by default.

To hear an answer, click the speaker under it, **Read Aloud** (Lire à haute voix). Qwen3-TTS does
not fit beside the 27B: the first sentence evicts the 27B and waits for Qwen3-TTS to load, about
15 s, and the next chat message waits for the 27B to load again.

## 7. Images

**Administrator → Images**, **Create Image** (Création d'image):

| Setting | Value |
|---|---|
| **Image Generation** (Génération d'image) | On |
| **Image Generation Engine** (Moteur de génération d'image) | **Default (Open AI)** (Par défaut (OpenAI)) |
| **API Base URL** (URL de base de l'API) | `http://10.0.2.2:8080/v1` |
| **API Key** (Clé API) | ai-ctl's key |
| **Model** (Modèle) | An image model (§8), typed |
| **Image Size** (Taille de l'image) | `1024x1024` |

**Edit Image** (Modification d'image), on the same page:

| Setting | Value |
|---|---|
| **Image Edit** (Modification d'image) | On |
| **Image Edit Engine** (Moteur de modification d'image) | **Default (Open AI)** (Par défaut (OpenAI)) |
| **API Base URL** (URL de base de l'API) | `http://10.0.2.2:8080/v1` |
| **API Key** (Clé API) | ai-ctl's key |
| **Model** (Modèle) | An image model (§8), typed |
| **Image Size** (Taille de l'image) | `1024x1024` |

**Administrator → Documents**, **Files** (Fichiers), below the retrieval settings:

| Setting | Value |
|---|---|
| **Image Compression Width** (Compression de la largeur de l'image) | `1024` |
| **Image Compression Height** (Compression de la hauteur de l'image) | `1024` |

- The image size is the size the image models make. At 1024×1024, an image or an edit takes
  from about 20 s to two minutes, depending on the model; at 2048×2048, from a minute to ten,
  an edit up to 27 ([stable-diffusion-cpp.md §4](image/stable-diffusion-cpp.md#4-models)). Each
  image model's budget is set for 4096×4096, so a larger size, asked from the command line or by
  the chat model, passes; it only takes longer.
- The compression is the size of the images you attach. The chat model reads an attached image
  with its projector on the CPU ([stack.md §5](stack.md#5-models)): about 25 s for a 1024×1024
  image, about 4 minutes for a 2048×2048 one or a phone's photo. OpenWebUI compresses an image
  when you upload it from your computer; a file picked from OpenWebUI's own list keeps the size
  it was uploaded at. The image model gets the compressed image too.
- The **Steps** (Étapes) are not sent to an `OpenAI` engine: each model's steps are the
  inventory's.

In a chat, open the input bar's **Integrations** menu and turn **Image** on, then ask for an
image. The toggle shows only when the settings the page loaded have image generation on: reload
the page after turning it on. Without the toggle, the chat model is given no image tool, and says
so. The chat model calls OpenWebUI's `generate_image` tool with a prompt of its own; with an
image attached, its `edit_image` tool, with the image's address, which OpenWebUI lists in the
message it sends. The chat model may give the tool a size of its own, which wins over the
setting: asked to edit a 2048×2048 image, the 27B asked for 2048×2048.

Each image model runs alone on the GPU: the request evicts the chat model, and the chat model
loads again to write its answer once the image is made. Loaded again, it reads the attached image
a second time. Checked on 2026-10-30 at 1024×1024: an image with Fibo 2.0 Dev in about 2 min 35 s
from the question to the answer, an edit with FLUX.3 Image Klein in about 2 minutes, of which
the 27B read the attached image twice, 26 and 30 s, and FLUX edited it in 22 s.

## 8. Another Model or Voice

OpenWebUI takes one model per engine. To switch, type another model's id in the engine's **Model**
field and save; the next request loads it. The ids are the inventory's: those it ships, with the
document that describes them.

| Engine | Models that fit | Notes |
|---|---|---|
| Speech to text | `whisper-large-v3-turbo`, `whisper-large-v3` ([whisper-cpp.md §4](audio/whisper-cpp.md#4-models)) | `qwen3-asr-1.7b` does not fit: it reads WAV only, and OpenWebUI sends MP3 or WebM |
| Text to speech | `qwen3-tts`, `qwen3-tts-q8`, `fish-s2-pro-q8`, `fish-s2-pro-bf16`, `voxtral-4b-tts` ([audio-cpp.md §5](audio/audio-cpp.md#5-models)) | The first four clone the library's voices; Voxtral speaks its own 20, such as `fr_female` and `fr_male` |
| Image generation and editing | `flux-3-image-klein`, `qwen-image-2.1`, `fibo-2.0-dev` ([stable-diffusion-cpp.md §4](image/stable-diffusion-cpp.md#4-models)) | Each makes and edits images |

To switch voices, type another voice in **TTS Voice**. A voice added to the library is used
without restarting anything.
