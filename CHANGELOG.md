# Changelog — ai-ctl

## 0.3.1 — unreleased

- llama.cpp built from its releases `vX.Y.Z` (roadmap `release-0-3-1`): `build`'s `latest`, `build outdated` and `build update` take llama.cpp's newest weekly release, its nightly tags `b<N>`, pre-releases, being no release; a commit both forms tag, such as `b12359`, is built as `v1.0.0`; a release is built with `LLAMA_BUILD_IS_DEV=OFF`, so that `llama-server --version` prints its version, `1.0.0`, where a commit no release tags still prints `1.0.0-dev`, an option no installed build is compared with; an installed `b<N>` build keeps serving and passing `doctor`, reads as built from a commit, and `build update` builds the newest release beside it, `build use` going back to it.

## 0.3.0 — 2026-11-13

- llama-swap v271 and its capacity router (roadmap `capabilities-status-and-updates`): `gateway install` installs v271 and no other, checked against its pinned SHA-256, its `--version` and `--sha256` removed with the release's own checksums as a source of digest: llama-swap is updated only through ai-ctl's pin, and `doctor` warns on a current release behind the pin, with `ai-ctl gateway install`, and on one ahead of it, which this ai-ctl was not tested with; the generated configuration runs the models on llama-swap's `capacity` router, each model taking its `vram_mib` from one pool, the GPU's usable memory less `vram_margin_mib`, and a model larger than the pool running alone, in place of the `matrix` sets ai-ctl computed, so that an inventory is no longer refused past 20000 sets; a margin that leaves the models none of the GPU's memory is refused by `doctor`, `gateway config` and `up`; `up` refuses, and `doctor` fails, a current llama-swap older than v267, which cannot read that configuration: run `ai-ctl gateway install` once after upgrading; `Cargo.toml`'s `rust-version` is 1.99.1, the toolchain `rust-toolchain.toml` pins.
- The models' capabilities: each model of the generated configuration declares them — what it reads and writes, whether it calls tools, the context of one request — from its kind and its inventory entry, which llama-swap shows clients in `/v1/models` before any model is loaded, so that a client picks a model by what it can do.
- `status --json` prints the same reading as `status` as one JSON document, for scripts and clients, its warnings on stderr and its exit codes those of the text.
- The builds behind their release: `build outdated` sets each current build beside its project's newest release, read with `git ls-remote`, and llama-swap beside the pinned release, exiting 4 when a project has something to build, and `build update` builds each of those at its newest release, a failure stopping that project only and no build removed; audio.cpp's key patch applies to v0.9.4, the release before it no longer taking it, and stable-diffusion.cpp's recipe fetches the CUTLASS the project now holds itself.
- The fixes of the roadmap's closing pass: a release tag its project withdrew leaves ai-ctl's clone at the next fetch, so that `build` and `build update` no longer take it for the newest release; `itoa` 1.0.18 → 1.0.19 and `syn` 3.0.9 → 3.0.10.
- The fixes of the review of 0.3.0's code (roadmap `review-skill-v2-5`): `up` runs a llama-swap release only once an ai-ctl checked its archive against the digest it pins for it, recorded in the release's directory, and `doctor` fails on one never checked, where it warned on a release behind or ahead of the pin, so any llama-swap ai-ctl 0.2.0 installed is refused until `ai-ctl gateway install`, to run once after upgrading, checks v271 again against its pin; a gateway whose binary `gateway install` replaced since it started is outdated for `status`, `doctor` and `up`, which name `ai-ctl down`, then `ai-ctl up`; a build off its recipe whose release its project withdrew fails `build update`, and the remedies of `up`, `gateway config` and `doctor` name `ai-ctl build <project>`, for the newest release, where they sent the user to rebuild a release no longer fetched; `build outdated`'s llama-swap line says `up` needs v267 for an older release, and its help names every state that exits 4; `errno` 0.3.14 → 0.3.15.
- A history started again from this release (roadmap `history-reset`), on a new remote: 0.2.0's release left with the old one, and the lines that follow are 0.2.0's, released on 2026-11-06.
- The v2 rebuild, on a new history with v1 archived as a bundle (roadmap `v2-rebuild`): ten commands around one declarative inventory — `init`, `doctor`, `build` with `list`, `use` and `prune`, `gateway install | config`, `up`, `down`, `status`, `logs` and `bench run | list | compare` —, a pinned llama-swap as the single gateway on `127.0.0.1:8080` and the only process that starts or stops a model.
- The fixes of its review (roadmap `v2-review-fixes`): the gateway and every backend answer only a client holding ai-ctl's key, a non-loopback `listen` needs `expose = true`, the inventory refuses unsafe values, downloads and images are pinned; the builds, the gateway's records and the bench's runs survive failures and interruptions; `doctor` from 690 to 247 ms.
- Speech and images (roadmap `audio-image-backends`): `whisper-server`, `audiocpp_server` and `sd-server` built natively by `ai-ctl build`, each patched to require ai-ctl's key, declared in the inventory as three new kinds and served by the gateway; the shipped inventory serves 13 models on four backends, used from OpenWebUI for transcription, speech, image generation and editing.
- The fixes of `audio-image-backends`' review (roadmap `review-skill-v2`): `toml` 1.1.8 → 1.2.0, with `toml_writer` 1.1.3 → 1.2.0, and `winnow` 1.0.4 → 1.0.5; `llama-server` built without its web UI, which its build downloaded from a mutable bucket outside the commit and compiled into the server; a current build made without a patch its recipe now applies, or without one of its recipe's CMake options at its value, such as a llama.cpp build made with its web UI, reported by `doctor` and refused by `up` and `gateway config`, with the command that builds it again; `doctor` no longer reads an `sd-server` model's `tokenizer`, a `tokenizer.json`, as a safetensors index, nor refuses the shards of an index under a `models_dir` holding `..`, and refuses a shard whose name `hf download` would read as an option; it needs a build only for the projects a model runs on, as `up` does, and says so when the inventory could not be read; `bench run` refuses a model of another server than llama-server before any request, which loaded it and evicted what could not sit beside it; a build whose patch could not be tried, such as on a full disk, no longer blames the patch nor sends to another release; a submodule a kill left without a commit during its first fetch is cloned again, where every later build of the project failed; `doctor` fails an `audiocpp_server` model whose directory holds nothing but `hf download`'s `.cache`, and says that a safetensors index is over its 16 MiB limit when the limit cuts a character, where it said the file was not UTF-8; an inventory whose models make more than 20000 sets of models that run together, which llama-swap starts more slowly than they grow, past `up`'s 30 s wait between 53000 and 84000, is refused by `doctor`, `gateway config` and `up`, before any start; `init --help` names the models' files as GGUF, safetensors or ggml, where it said GGUF.
- A history started again and a release workflow (roadmap `fresh-history-and-ci`): the Rust toolchain pinned at 1.99.1 by `rust-toolchain.toml`; each tag `vX.Y.Z` refused unless it is `Cargo.toml`'s version with a dated entry here, then checked and built in Fedora 44 by GitHub Actions and published with its `SHA256SUMS` on the tag's release, which production installs with `gh release download`; `toml` 1.2.0 → 1.2.1, with `serde_spanned` 1.1.2 → 1.1.3 and `toml_datetime` 1.1.2 → 1.1.3.
